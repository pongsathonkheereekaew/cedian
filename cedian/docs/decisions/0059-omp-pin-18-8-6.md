# ADR-0059: The OMP pin moves to 18.8.6 before the benchmark; Stop uses `abort_and_restore_queue`

- **Status:** Accepted (owner, 2026-10-10, in chat: "bump pin เป็น 18.8.6 ก่อน แล้วค่อย bench", "เทียบกับ S2 เดิม บอกไว้ว่า OMP ต่างเวอร์ชัน", "ตอน bump เลย", "เพดานเป็น 45")
- **Date:** 2026-10-10
- **Rule text:** `vendor/omp-revision.json`, the fork's `cedian/OMP_PARITY.md`; `docs/plans/done/s9-real-app.md` U12
- **Supersedes:** ADR-0058 decision 1 (the pinned OMP 18.6.1) and the 40-turn cap in decision 5
- **Builds on:** ADR-0003, ADR-0034, ADR-0057 decision 4

## Context

On 2026-10-09 the owner's `~/.local/bin/omp` updated itself to 18.8.6. The pinned 18.6.1 survives only as a `.bak` file. The owner's OMP databases in `~/.omp/agent` are now written by 18.8.6, so running 18.6.1 against them could damage them.

cedian's vendored `wire.rs` was never exactly 18.6.1's. It came from upstream commit `fc6c0c90`, which is later than tag v18.6.1. Tag v18.8.6 (upstream `f068751e`) is reachable from this machine. Between the two, OMP added these commands:

- `get_logout_accounts` and `logout`;
- `abort_and_restore_queue`, which was already in the vendored wire but not in the 18.6.1 binary.

`open_session` and `switch_session` gained optional model fields. OMP's docs say that removing each queued message and then aborting "races the agent loop", and in 18.8.6 a plain `abort` can feed a queued steer into a fresh turn.

## Decision

1. **The pin is OMP 18.8.6** (owner). `wire.rs` is taken from tag v18.8.6, and `vendor/omp-revision.json` and `OMP_PARITY.md` change in the same change (ADR-0034). The new commands get rows: logout is `deferred: S10`, and `abort_and_restore_queue` is `native`.
2. **Stop uses `abort_and_restore_queue`** (owner). It returns the queue and aborts in one command. The U8/U10 take-back keeps its rules: a chat message goes back to the composer, an inline edit is named in the notice, and a message OMP already took into a run is named, never restored.
3. **A live smoke on 18.8.6 runs before the benchmark.** It checks resume, the benchmark model's availability, the approval prompt for `bash` and `eval`, Stop with a queued message, and an edit's before-text.
4. **The live pass is capped at 45 model turns** (owner): the smoke, then the fixture re-records, then B1–B10 in both arms.
5. **The benchmark compares with S2 and says the OMP versions differ** (owner). The 25 % rule becomes a warning, not a verdict. A difference cannot be split cleanly between cedian and OMP.

## Consequences

- Every fixture still replays, because none of the frames they use changed shape. The re-recordings in U12 are made on 18.8.6.
- `abort_and_prompt` (still `deferred: S9 U11`) can build on `abort_and_restore_queue`.
- OMP will keep updating itself on this machine. A pin that differs from the installed binary is caught at launch with the ADR-0057 warning.
