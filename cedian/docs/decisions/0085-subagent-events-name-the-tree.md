# ADR-0085: A subagent's events name the directory it works in; a write is attributed to the worker whose tree holds it

- **Status:** Accepted (agent, 2026-10-16, under ADR-0077 decision 2's "S5's worktree attribution works through a fork patch to OMP's subagent events"; the field shape is the upstream draft the owner saw on 2026-10-14, `~/.cache/cedian-s10/S5-upstream/request.md`)
- **Date:** 2026-10-16
- **Rule text:** fork `packages/coding-agent/src/task/executor.ts` (the lifecycle and progress payloads), `src/modes/rpc/wire/frames.ts` and `wire/state.ts` (`cwd`, `worktree`), `src/task/types.ts` and `src/task/index.ts` (the `task` tool's `cwd`); app `crates/cedian_worker/src/brief.rs` (`WorkerScope::attribute`), `crates/cedian_agent_ui/src/subagents.rs` (`SubagentRow::cwd`, `SubagentTree::working_in`), `crates/cedian_panel/src/review.rs` (`UnreviewedWrite`, `out_of_scope_count`), `crates/cedian_panel/src/panel.rs` (`attribute_write`, `merge_worker`)
- **Implements:** ADR-0077 decision 2 (S5's attribution through a fork patch)
- **Supersedes:** ADR-0063 (the union of running briefs as the turn's scope)
- **Builds on:** ADR-0050 (a worker is an OMP subagent; worktrees are cedian's), ADR-0033 (the brief contract), ADR-0075 (the narrow fork)

## Context

OMP's `subagent_lifecycle` and `subagent_progress` frames and its `get_subagents` rows carry an id, a session file and the parent tool call, but not the directory the subagent works in. ADR-0063 therefore classified an imported hunk against the union of every running worker's brief, which cannot say which worker a file belongs to, and the S5 exit item "which subagent works in which tree" stayed open (ADR-0068). ADR-0075 made OMP a fork, so the frames can grow the field.

A second gap sat under the first. ADR-0050 decision 2 pins OMP's task isolation off, so every subagent runs in the session's cwd, the workspace. Naming that directory would name the same one for every subagent. The agent needs a way to run a worker inside the tree cedian made for it.

## Decision

1. **The fork names the directory.** `SubagentLifecyclePayload`, `SubagentProgressPayload` and `SubagentSnapshot` gain two optional fields: `cwd`, the absolute path of the directory the subagent works in (its isolated worktree when OMP made one, else its cwd), and `worktree`, set only when OMP made an isolated tree, equal to `cwd` then. Both optional, so a host that does not read them is unaffected. `subagent_event` needs nothing: its `id` joins to the lifecycle row.
2. **The `task` tool takes a `cwd` per spawn** (flat form and each `tasks[]` item): the directory the subagent runs in, resolved against the session's cwd, refused before any spawn when it is not an existing directory. `cedian_worktree_request` already replies with the tree's absolute path; the agent passes it as the worker's `cwd`. OMP's isolation stays pinned off (ADR-0050 decision 2), so the tree is still cedian's. With `isolated: true` OMP builds its own tree from the session's cwd and ignores the given `cwd`; the events then carry that tree as both `cwd` and `worktree`. The cwd keeps the session's additional directories. A follow-up turn and an IRC wake turn name the same directory as the first turn.
3. **The app shows the tree on the row.** A subagent row names its `cwd` relative to the workspace root when it differs from the root (`in .worktrees/w1`), the absolute path when it lies outside, nothing when it is the root or unknown, and says so when OMP made the tree itself.
4. **A write is attributed by tree, not by union.** The turn's scope is one entry per running worker, keyed by its tree root (`<repo>/<worktree>`). A changed path under a root is that worker's: tree-relative, it is judged by that worker's brief alone, in scope or `OutOfScope`. A path under no running worker's tree is not classified, since no brief claims it; ADR-0063's "a workspace write is out of every brief" is gone with the union. The subagent working in a tree is the one whose `cwd` is that root, and the audit row of a breach names the worker and that subagent.
5. **A `task` call's disk writes are watched like a `bash` call's.** The panel already lists the files not open that changed while a `bash` call ran (ADR-0047). A `task` call is the same kind of call: its subagents write to disk and the app sees no edit tool call. Each such path is attributed per decision 4: in scope advances that worker's `last_progress` (ADR-0033 decision 5); out of scope writes the audit row and is listed on the review as written by that subagent outside its brief.
6. **An out-of-scope write to a file nobody has open blocks Merge, like an `OutOfScope` hunk.** The listing from decision 5 carries the write as awaiting a decision (`UnreviewedWrite::out_of_scope`, the absolute path). `out_of_scope_count` counts it, so Merge is refused with the same notice as for a hunk (ADR-0033 decision 3), and Accept all skips it. The Review Changes line gets Open, which shows the file in the workspace, and Accept, which keeps the write on disk and clears the block; the line stays as a record. There is no Reject: cedian has no text from before the call, so the person reverts in the editor if they want to. Fail closed: a write the app cannot review is not one Merge may take unseen.
7. **A spawn's `cwd` is bounded.** The fork refuses a `cwd` whose realpath is not under the session cwd's realpath or a `tools.readScope` root or allow folder, and one that passes through `.git` or a read-scope protected name below that root. A symlink that leads out is judged by where it leads. The refusal names the path and comes before any spawn. A model cannot move a subagent to `/`, a sibling checkout or the repository's `.git` by naming it.
8. **Paths are compared as the filesystem spells them.** `WorkerScope` canonicalizes each tree root and each attributed path (symlinks resolved, `/var` meets `/private/var`; a part that does not exist yet is kept as written), and the subagent lookup canonicalizes the row's `cwd` the same way. A worker tree is usually gitignored: when a `bash` or `task` call starts, the panel has the project scan each running worker's tree in full, and a change under one is attributed even though it is ignored.
9. **Merge waits only on its own worker.** Each out-of-scope hunk and write records the worker whose tree holds it; Merge of worker `w1` is refused only while a change in `w1`'s tree awaits a decision. A wake turn of an isolated subagent carries `worktree` like its first turn, and the app does not clear a row's isolated mark on a later frame that names the same tree without it.

## Consequences

- S5's last exit item closes: the panel shows which subagent works in which tree, and an out-of-scope write is tied to one worker and one subagent, proven by the fork's tests at the payload layer (`test/rpc-subagents.test.ts`, `test/task/task-cwd.test.ts`), the app's fake-omp replays with `cwd` in their frames (`cedian_panel/tests/subagents.rs` step 6b, `tests/worker_trees.rs` step 2b, on files the person has open) and the panel's `FakeFs` tests for a write to a file nobody has open (`panel.rs`, `a_task_calls_disk_writes_are_attributed_to_its_subagents_tree`).
- The replays reach only files that are open: the worktree watcher does not fire under the replay executor, so the not-open path of decision 5 and the Merge block of decision 6 are proven at the panel unit level with `FakeFs`, not in a replay. A replay of that path waits on a watcher the test executor drives.
- The agent's own prompts and skills that spawn workers must pass the tree as `cwd`; a worker spawned without it runs in the workspace and its writes fall under no tree, so they are not classified. That is the honest reading of such a spawn, not a breach.
- The fork gains one tool parameter and two optional fields on three payloads; an upstream merge touches the executor's five emit sites and the `task` schema variants. The parity ledger carries both.
- ADR-0063's tests that placed a worker's files in the workspace root moved under the worker's tree; "no running worker, nothing classified" still holds.
